# Florence Mobile (Android)

<div align="center">

**Native Android companion for the Florence investment platform** — live BIST market data, currency & precious metals, AI-powered research reports, and a virtual portfolio simulator.

Florence Mobile is the mobile counterpart of the [Florence web interface](https://github.com/project-florence/web) and the [Florence backend](https://github.com/project-florence/backend). It talks to the same `/api/v1` endpoints, uses the same shared database, and behaves exactly like the web app — so accounts, portfolios, credits, and reports work identically across both platforms.

## ✨ Features

- **Live BIST dashboard** — market status, top movers, popular stocks with mini sparkline charts
- **Stock search & detail** — company fundamentals, interactive candlestick charts drawn with pure Compose Canvas (no third-party chart library)
- **Currencies & Metals** — official TCMB exchange rates with gold-api fallback; gold types (gram, quarter, half, full…), silver, platinum, palladium
- **AI Research Reports** — quick & deep reports generated by a local LLM (Ollama, `qwen2.5:7b`), no internet LLM required; credit-based pricing shown upfront
- **Virtual Portfolio** — buy/sell simulation with real-time market prices, positions, P&L, and transaction history
- **Coin / Credit System** — balance shown on the dashboard, consumed by report generation, recharged via admin endpoints
- **Watchlist (Favorites)** — one-tap tracking of stocks
- **IPO Listings** — upcoming and recent public offerings
- **Notifications** — notification center screen
- **i18n & Theming** — Turkish by default, English available; light/dark theme
- **Drawer navigation** with custom app logo; splash & auth screens
- **Dev / Prod build flavors** — local backend (`10.0.2.2:7055`) vs production API

## 🛠 Tech Stack

- **Kotlin 2.x** + **Jetpack Compose** (Material 3), Navigation Compose
- **Hilt** for dependency injection, **KSP** for code generation
- **Retrofit + OkHttp + kotlinx.serialization** — typed, safe API layer
- **EncryptedSharedPreferences** for the refresh token; access token kept in memory
- **MVVM + Repository** architecture, single-flight token refresh
- **Pure Compose Canvas** for all charts (no third-party chart dependency)
- minSdk 26 / targetSdk 36

## 🏗 Architecture

```
app/src/main/java/com/florence/app/
├── core/          # network (interceptor/authenticator), token storage, theme, DI
├── data/          # Retrofit API interface, DTOs, repositories
└── presentation/  # Compose screens, ViewModels, navigation
```

The API layer is plain Kotlin + kotlinx.serialization — it can be lifted into a KMP module if an iOS target is ever added.

## 🚀 Getting Started

### Prerequisites

- JDK 21 (Android Studio JBR) — configured via `org.gradle.java.home` in `gradle.properties`
- Android SDK
- The Florence backend running locally on port `7055` (see the [backend repo](https://github.com/project-florence/backend))

### Build

```bash
# Dev flavor (local backend at http://10.0.2.2:7055)
./gradlew :app:assembleDevDebug

# Prod flavor
./gradlew :app:assembleProdDebug
```

> Windows note: `GRADLE_USER_HOME` is pinned to `C:/gradle-home` (inside `gradlew`) and the project lives in an apostrophe-free path because the `GAMER'S` user folder breaks Java's @argfile parsing.

### Run on an emulator against the local backend

If the backend is up (Docker Compose, port `7055`), the emulator reaches it at `10.0.2.2:7055`. Alternatively:

```bash
adb reverse tcp:7055 tcp:7055   # then use localhost:7055
```

Cleartext HTTP is allowed only for dev hosts (`res/xml/network_security_config.xml`).

## 🔐 Authentication (backend-compatible)

- Login: `POST /api/v1/auth/login` — **form-encoded** (`OAuth2PasswordRequestForm`), returns a JSON token pair
- Access token lives 1 hour; `TokenRefreshAuthenticator` performs a single-flight refresh on 401 and retries the request
- Refresh: `POST /api/v1/auth/refresh` (JSON `{ refresh_token }`) — backend rate limit 5 req/min
- Same accounts as web: one shared `users` table, no platform separation
